# i18n

Frontend internationalization for the SPA. **Paraglide JS 2.x** compiles hand-authored message files into per-message tree-shakable functions; a single locale rune + legacy-store mirror drive reactive re-render and `<html dir/lang>`. Currently `en` (base) + `ar`. This doc is the *what-is* contract; the **`i18n` skill** (`.claude/skills/i18n/`) is the *how-to* (adding a string, localizing a surface, the bidi conventions). Don't restate one in the other.

**Scope of the strings layer.** Workflows 1–2 ship Arabic *strings* with the chrome staying **LTR** — physical layout is not flipped. The full RTL layout pass is a separate, later workflow. See [`docs/planning/i18n.md`](../planning/i18n.md) for the workflow sequencing and the locked decisions; the present doc describes what is wired today.

## Message files — split by area, prefixed flat keys

Messages are **hand-authored** JSON (not extracted from code), one file per locale per area. The `pathPattern` in `settings.json` is an **array**, listing each area dir and `common` **last** so the inlang editor exports new keys into `common` by default:

```
./src/tabs/dashboard/messages/{locale}.json
./src/tabs/timestamps/messages/{locale}.json
./src/tabs/segments/messages/{locale}.json
./src/lib/i18n/messages/common/{locale}.json
```

Keys are **flat, prefixed by area** so the namespace stays collision-free across files: `common_action_save`, `common_auth_sign_in`, `common_signin_edit_title`, … (per-tab files use `dashboard_*` / `timestamps_*` / `segments_*`). Paraglide flattens all files into one global message map, so the prefix *is* the namespace — there is no nesting. Every key MUST exist in **both** `en` and `ar` for an area (parity); a test enforces this (below).

Arabic chrome copy is **MSA, no tashkeel** (vowel marks are for Quranic text, not UI labels). Quranic text and reciter names are data, not UI strings — they are never translated (see boundary below).

## Compile + build-order wiring

The repo's `check`/`build` run `svelte-check`/`tsc` **before** Vite, so the generated `src/lib/paraglide/` dir must already exist when type-checking starts. A reusable `paraglide:compile` npm script is chained ahead of every entry point (`inspector/frontend/package.json`):

| Script | What |
|---|---|
| `paraglide:compile` | `npx --no-install @inlang/paraglide-js compile --project ./project.inlang --outdir ./src/lib/paraglide --strategy localStorage preferredLanguage baseLocale --output-structure message-modules --emit-ts-declarations` |
| `postinstall` | `npm run paraglide:compile` — so fresh `npm ci` / CI / worktrees have the dir before anything reads it |
| `dev` / `build` / `check` / `typecheck` | each prefixed with `npm run paraglide:compile &&` |

On `dev`/`build` the **`paraglideVitePlugin`** also recompiles (`vite.config.ts`) — this pass is what stamps the runtime strategy + `localStorageKey: 'insp_locale'` into the bundle.

**Two CLI-vs-plugin facts to know** (the 2.20.1 CLI and the Vite plugin don't take the same flags):
- The CLI has **no `--localStorageKey` flag**, and `--strategy` takes **space-separated** items (not repeated flags). The localStorage key is configured on the **Vite plugin only**; the CLI pass exists purely to materialize the dir for `tsc`/`svelte-check`, and the plugin re-stamps the real runtime strategy/key on `dev`/`build`.
- `--emit-ts-declarations` (CLI) + `emitTsDeclarations: true` (plugin) are **required**: the generated runtime is `.js` with JSDoc, and under this repo's strict `allowJs: false` tsconfig `svelte-check` errors "Could not find a declaration file" for every `$lib/paraglide/*` import without the `.d.ts` companions.

A `$lib` → `src/lib` resolve alias was added in **three** places so the documented `$lib/paraglide/...` import style resolves everywhere: `vite.config.ts` (`resolve.alias`), `tsconfig.json` (`paths`), and `vitest.config.ts` (`resolve.alias` — vitest has its own config; without it the `$lib/paraglide/*` imports fail to resolve in tests).

## Locale rune + dir/lang plumbing

Two reactive mirrors of Paraglide's *ambient* locale, kept in lockstep by one switch:

- **Runes** (`locale.svelte.ts`): `i18n.locale` is a `$state` cell. Reading it in a template or `$derived` registers a dependency; the write on switch trips re-render. Seeded from `getLocale()` (Paraglide's own localStorage → preferredLanguage → baseLocale resolution).
- **Legacy** (`locale-store.ts`): `localeStore` is a `writable`. Legacy Svelte-4 files (e.g. `App.svelte`) re-render off `$localeStore`. Because `tsc` rejects the `($localeStore, m())` comma-operator trick as an unused expression, the bridge helper `tr($localeStore, m_fn())` carries the dependency while returning the string: `$: label = tr($localeStore, common_auth_sign_out());`.

**One switch funnel.** Every switcher routes through `switchLocale(next)` (`locale-store.ts`), which:
1. `setLocale(next, { reload: false })` — updates Paraglide's ambient locale + persists via the localStorage strategy under `insp_locale`,
2. `localeStore.set(next)` — trips legacy subscribers,
3. `runeSetter?.(next)` — trips the runes cell (registered once by `locale.svelte.ts` via `registerRuneSetter`, avoiding a `.ts → .svelte.ts` import),
4. `applyDocument(next)` — sets `<html lang>` and `<html dir>` (`rtl` for `ar`, else `ltr`).

`initLocale()` is called once in `main.ts` before mount (mirroring `installAudioWarmup`) to sync `<html dir/lang>` with the resolved boot locale. **Note:** switching to Arabic already flips `<html dir="rtl">` today — the chrome is not yet restyled for RTL, so the strings-only workflows keep the layout LTR in practice (interim bidi per PRODUCT.md); the layout flip is the later RTL workflow.

## Message consumption

Per-message functions are deep-imported from the generated tree: `import { common_signin_edit_title } from '$lib/paraglide/messages/common_signin_edit_title';` then called `common_signin_edit_title()`. Each call reads the current ambient locale at *access* time. Two consumption shapes are in use:
- **Lazy getters** (`sign-in-messages.ts`) — `title`/`body` getters call the message fn on access, so a modal snapshots copy in the locale current when it opens.
- **`$:` + `tr()`** (`App.svelte`) — legacy reactive labels recompute when `$localeStore` changes.

Runes components read `i18n.locale` directly (e.g. `LocaleSwitcher` for its active-state highlight).

## Generated-output handling + exclusions

`src/lib/paraglide/` is regenerated on every install/dev/build by its own toolchain (unlike the committed Pydantic→TS schema codegen, this is **never committed**). It is excluded at every gate:

| Exclusion point | File |
|---|---|
| Git | `inspector/frontend/.gitignore` (`src/lib/paraglide/`) — plus the compiler emits its own `.gitignore` (`*`) inside the dir |
| eslint | `inspector/frontend/eslint.config.js` `ignores` |
| lint-staged | `lint-staged.config.mjs` (skipped alongside `src/lib/types/generated/`) |
| Vitest coverage | `inspector/frontend/vitest.config.ts` `coverage.exclude` |

## Do / don't translate boundary

| Translate (UI chrome) | Never translate (data) |
|---|---|
| Buttons, labels, prompts, modal copy, toasts, empty states | Quranic Arabic text + tashkeel (rendered as-is from the shard/refs) |
| Tab names, filter labels, validation card headings | Reciter names + transliterations (catalog data; `ar`/`en` pairing is a data concern, not i18n) |
| | Riwayah / style / source vocabulary slugs (catalog vocab → `delivery-label.ts`, not message files) |
| | Phoneme glyphs, waqf marks, technical metadata values |

Catalog vocabulary display names already live in `lib/utils/delivery-label.ts` / `axis-labels.ts` and stay there — they are not message keys.

## Verification / CI

- **`npm run check`** (compile → `svelte-check`) — type-checks every `$lib/paraglide/*` import; passes because of the `.d.ts` companions + the `$lib` alias. Run before pushing.
- **`npm run build`** (compile → `tsc` → `vite build`) — the Vite plugin recompiles and stamps `insp_locale`; verify a localized string lands in both locales in `dist/assets/index-*.js`.
- **`npm run test`** (vitest) — message-parity test asserts each area's `en`/`ar` key sets are identical and all seed files are valid JSON.
- No new CI job was added; i18n rides the existing FE `check`/`build`/`test` gates. The generated dir's exclusions keep it out of lint/coverage/codegen diffs.
