# i18n — plan

The multi-workflow plan for internationalizing the Inspector SPA. This is the *why* + *sequencing*; the *what-is* contract for the wired foundation is [`docs/reference/i18n.md`](../reference/i18n.md), and the *how-to* is the **`i18n` skill** (`.claude/skills/i18n/`).

The driving constraint: ship Arabic **strings** first and verify them with the chrome unchanged, then do the full RTL **layout** flip as a separate, later workflow. Strings and layout are decoupled so a bug in either can't block the other.

## Locked decisions

| Decision | Choice |
|---|---|
| Library | **Paraglide JS 2.x** (`@inlang/paraglide-js`) — compile-time, tree-shakable per-message functions; no runtime ICU interpreter |
| Message file org | **Split by tab/area + a `common` file**, one JSON per locale per area; `pathPattern` is an array with `common` last |
| Keys | **Flat, prefixed by area** (`common_*`, `dashboard_*`, `timestamps_*`, `segments_*`), **hand-authored** (not code-extracted) |
| Locales | `en` (base) + `ar`; Arabic chrome = MSA, no tashkeel |
| Strings vs layout | **Separate workflows.** Strings ship first with LTR chrome (interim bidi per the Arabic conventions in PRODUCT.md). Full RTL layout flip runs **after** the strings workflow is verified |
| Coverage order | **Public surfaces first** (Dashboard + Timestamps) → user approves → **then** Segments. Admin is English-default, lowest priority |
| RTL principle owner | The RTL workflow updates PRODUCT.md's "RTL is preserved inside Arabic fields without flipping the whole component" principle (line ~71) |

## Workflow sequencing

### Workflow 0 — foundation — **DONE**

Paraglide installed + wired, the locale rune/store + switcher built, the skill authored, and these docs written. Verified: `check` / `build` / `test` all green; a localized proof slice (sign-in copy + header auth labels) round-trips EN/AR in the production bundle.

Delivered:
- Paraglide 2.20.1 + plugin-message-format 4.4.0 (exact pins), `project.inlang/settings.json` (array `pathPattern`).
- `src/lib/i18n/` — `locale.svelte.ts` (rune), `locale-store.ts` (legacy mirror + `switchLocale` + `tr()`), `messages/common/{en,ar}.json`.
- Empty per-tab seed message files for dashboard / timestamps / segments.
- `LocaleSwitcher.svelte` mounted in the App header; `initLocale()` in `main.ts`.
- Build-order fix (`paraglide:compile` chained ahead of `check`/`build`/`typecheck`/`dev` + `postinstall`); `$lib` alias in vite/tsconfig/vitest; generated dir excluded from git/eslint/lint-staged/coverage.
- Proof slice: `sign-in-messages.ts` + header auth labels localized.

Full wiring detail lives in [`docs/reference/i18n.md`](../reference/i18n.md).

### Workflow 1 — localize PUBLIC surfaces (Dashboard + Timestamps) — strings only

Translate the user-facing chrome of the two public tabs into Arabic. **Strings only — chrome stays LTR.**

Scope:
- Extract every UI string in `tabs/dashboard/` and `tabs/timestamps/` into `dashboard_*` / `timestamps_*` message keys, author the `ar` parity.
- Wire the `m.*()` reads (runes components read directly; legacy components via `$localeStore` + `tr()`).
- Keep physical layout unchanged: no CSS logical-property pass, no mirroring. Arabic renders in LTR chrome with per-field bidi (the existing PRODUCT.md interim handling).
- **Do not** translate Quranic text, reciter names, or catalog vocabulary (the do/don't boundary in the reference doc).

Exit criteria: both tabs fully localized, `en`/`ar` parity test green, `check`/`build`/`test` green, switcher flips all visible chrome copy in-place. Then **stop for user approval** before proceeding.

### → User approval gate

The user reviews Workflow 1 in the browser and approves before Segments begins. Do not roll into Workflow 2 automatically.

### Workflow 2 — localize Segments — strings only

Same playbook as Workflow 1, applied to `tabs/segments/` (`segments_*` keys). Larger surface (editor, filters, validation accordions, history, shortcuts guide). Still strings only, LTR chrome. Admin surfaces stay English-default and are not localized in this workflow (lowest priority).

### Later workflow — full RTL layout flip

A distinct workflow, run only after the strings layers are verified. This is a **layout** pass, not a strings pass.

Scope:
- **Physical → logical CSS.** Convert directional properties to logical equivalents (`margin-left` → `margin-inline-start`, `left` → `inset-inline-start`, `text-align: left` → `start`, etc.) so the whole layout mirrors under `dir="rtl"`.
- **Time-axis `dir="ltr"` islands.** Anything whose semantics are temporal/left-to-right stays LTR even in an RTL document: the waveform, the filmstrip ruler, the teleprompter time-flow, segment time ranges, charts. These are explicit `dir="ltr"` islands — time never flows right-to-left.
- **Icon mirroring** for directional glyphs (chevrons, back/forward, undo/redo) — but not for non-directional or time-oriented ones.
- **Arabic typography** — line-height, tracking, font pairing for Arabic chrome at UI sizes (distinct from Quranic-text typography).
- **Update PRODUCT.md** — revise the "don't flip the whole component" principle to reflect that the app now *does* flip layout at the document level under RTL, while the time-axis islands and Arabic-data fields keep their own direction.

#### RTL recon facts (for this future workflow)

- **~15:1 physical : logical** — the codebase currently uses physical directional CSS roughly 15× more than logical, so the logical-property conversion is the bulk of the layout work and is mechanical-but-wide. Budget for a broad sweep, not a few files.
- **Time-axis no-flip islands** — the waveform / filmstrip ruler / teleprompter / time-range / chart surfaces must NOT mirror; they are pinned `dir="ltr"`. Identify and island these explicitly before the global flip, or the time axes invert.
